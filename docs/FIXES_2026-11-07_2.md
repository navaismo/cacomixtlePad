# Second round of fixes

Date: 2026-11-07. This continues the first round; changes remain local on
`9f7a9e1`. We have not published or committed any changes yet.

## Outstanding issues resolved in code

- **Release signing:** we removed implicit selection of the debug certificate.
  Gradle accepts `android/key.properties` or environment variables and requires
  all four fields. A release without configuration fails with an actionable
  message. Explicit unsigned validation never selects debug signing.
- **Key creation:** we prepared a template and the interactive script
  `tool/create_release_key.sh`. Enter your details and password in your
  terminal; the script rejects an existing destination. We still need to
  create our distribution key. See [RELEASE.md](RELEASE.md).
- **License:** we chose AGPL v3, declared `AGPL-3.0-only`, and added GNU's
  official text in `LICENSE` without modifications.
- **CI:** `.github/workflows/ci.yml` runs formatting, translations, analysis,
  tests, the debug build, and signing validation. It pins Flutter 3.29.3 and
  actions by commit, uses read permissions, and keeps only the test APK.
  We prepared it locally; we have not run it on GitHub yet.
- **Resend:** the Android connection initializes numbering, sends checksums,
  and retries the pending line up to three times when the requested number
  matches. It consumes the resend notice ACK before waiting for the command
  ACK. An old number, loss of synchronization, thermal failure, reset, or
  exhausted retries invalidates the session. We checked the implementation
  against the [Marlin protocol](https://marlinfw.org/docs/features/host_interface.html).
- **State after a process restart:** we save the last job before the first
  send, every five seconds, and on state changes. When you reopen the library,
  an active record appears as “Interrupted.” We restore its name, layers,
  progress, and elapsed time without sending commands. You can view it from
  “Last print.” This recovers the record, not the physical position or a
  running print.
- **Final-state saving:** we serialize checkpoints and prevent cancellation
  of an already completed job while saving its result. If the first save
  fails, the job does not start sending commands. We reject invalid records
  and show history errors on screen.

## Validation

- 47 passing Flutter tests, including the service → numbered protocol →
  checksum/Resend/ACK path, fragmented retries, limits and errors, restoration
  after interruption, persistence failure, and cancellation during final-state
  saving.
- Static analysis without issues and Dart formatting checked.
- Seven translation files with 95 keys each, also checked through the CI script.
- Workflow YAML validated locally and action inputs reviewed.
- Dependencies resolved from cache with `--enforce-lockfile`.
- Successful debug APK build.
- `tool/validate_release_signing.py` confirmed three real cases: rejection of
  a release without a key; a release signed with a temporary certificate whose
  SHA-256 matches the APK's; and an explicitly unsigned release even with
  signing values present. We restored previous artifacts and removed the
  temporary validation certificate, key, and APKs.
- We verified that the previous APK in `package/` and the local debug APK use
  the same certificate. A future dedicated key will change that identity;
  installation migration is covered in [RELEASE.md](RELEASE.md).
