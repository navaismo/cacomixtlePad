# First round of fixes

Date: 2026-11-07. Local changes based on `9f7a9e1`, not yet committed.
We update the [initial analysis](REPO_ANALYSIS.md) here. We address this round's
outstanding work in the [second round](FIXES_2026-11-07_2.md).

## Implemented changes

- We centralized USB reception with line buffering and a shared FIFO for
  printing, controls, and queries. Fragments and multiple ACKs in one packet
  no longer release commands that have not been sent. Firmware, statistics,
  and mesh queries use the full response through ACK.
- We added an ACK timeout with keepalive and an absolute limit. On an error,
  `Resend`, reset during a command, disconnection, or write failure, we
  invalidate the session and stop sending lines without synchronization.
- We fixed temperature polling to prevent accumulated listeners and a growing
  backlog of queries. We cancel subscriptions and timers on disconnect and
  in `dispose`.
- We moved printing into a shared service independent of its screen's
  lifecycle. We read G-code as a stream and provide access to the active job
  from the library. We preserve state, progress, and errors when you reopen it.
- We wait for the last ACK and `M400` before completing a job. We added sender
  pause, cancellation during printing or the final barrier, and explicit
  failure on connection loss.
- We removed the drop to an absolute Z and the model-dependent parking move
  from cancellation. We turn off the hotend/bed/fan and wait for accepted
  movements. Cancellation is not immediate during a blocking command.
- We block manual movement, motor, and configuration commands that conflict
  with an active job. For manual extrusion, we set `M83` and check the reported
  temperature; we removed simulated heating based on a fixed delay.
- We created a shared file repository with validated names, size limits,
  staging, failure cleanup, collision rejection, and locking during printing.
  The API processes multipart data as a stream, and the library refreshes
  after changes.
- We added upload authentication with `X-Api-Key` and a persisted key that you
  can view and copy from Home. We updated the Postman/cURL, Orca, and Cura
  instructions.
- We separated loading, error, and empty states in the library. We made the
  import button available without files or USB and added a retry option.
  We prevent invalid thumbnails from breaking the screen.
- We added loading and saving of persisted preset values, with number/range
  validation and defaults shared with Home. We standardized the PLA bed
  temperature at 60 °C.
- We handle storage errors and permissions. We select permissions according
  to the Android SDK level, made API 29 adjustments, and added permission to
  read Wi-Fi state.
- We close the server when the root is unmounted and added `mounted` checks
  after asynchronous operations. We only report `M500` success after receiving
  confirmation from the printer.
- We respect the saved language at startup, aligned translation keys, and
  fixed lints. We declared analysis/test dependencies and `path` directly.
- We replaced the obsolete counter test with protocol, service, storage/API,
  temperature, and widget tests. We stopped ignoring tests, analysis
  configuration, and the lockfile.

## Validation

Final results:

- `flutter analyze --no-pub`: zero issues.
- `flutter test --no-pub --reporter expanded`: 31 passing tests.
- `flutter build apk --debug --no-pub`: successful build; artifact at
  `build/app/outputs/flutter-apk/app-debug.apk`.
- Seven valid JSON files, 91 keys per language, and no literal key used through
  `.tr()` missing from English.
- `git diff --check` and Dart formatting checks passed.

The tests cover response fragmentation and coalescence, interleaved queries,
errors/disconnection, timeout/keepalive, pause/resume, cancellation and the
final barrier, file locking, authentication, paths and collisions, upload
limits/cleanup, permission retries, metadata/mesh, polling without duplication,
an empty library, presets, and leaving the active route.

## Still to validate or resolve

We did not connect a printer or install the APK on a phone during this round.
We still need hardware checks for the connection after DTR, this firmware's
response to `M400`, heating, pause/cancel, leveling, extrusion, and uploads
from slicers. Builds and tests do not replace those physical checks.

At the end of this round, we still used the original debug signature for
releases and had not defined a distribution key. We also needed to specify
the AGPL version and include its text. We had not yet added CI or job recovery
after process death. `Resend` stops and fails the job without automatic retries.

We left the web dashboard and phone video for the next phase, following our
agreed order of work.
